# 静态检测规则补全方案（30 条 → 58 条）

> 针对 PPT《04 后续改进·静态增益》页"30 条内置规则"的全面性评估与补全。
> 评估基准：MISRA C:2012、SEI CERT C、CWE、GJB 8114/5369、本组硬件语义调研（§7）。
> 现状代码核实：`ecdet/l3_analysis/builtin_rules/rules_meta.py`（实际 30 条）、`hw_model/`（SVD 解析/ISR 识别/RTOS API 语义已具备）、`gjb_map.json`（主题映射，verified=false）。

---

## 一、现状盘点（与 PPT 页面对应）

| 类别 | 条数 | 现有规则 | 判定层 |
|------|------|----------|--------|
| MISRA C:2012 子集 | 17 | 2.5/7.2/8.7/8.9/10.3/10.4/13.5/14.2/15.2/15.5/16.4/16.6/17.2/17.3/21.1/21.3/21.6 | 句法为主，10.x 走类型求值 |

## 二、差距分析

| 基准 | 规模 | 我们覆盖 | 主要缺口 |
|------|------|----------|----------|
| MISRA C:2012 | 16 指令 + 143 规则 = 159 | 17（10.7%） | **初始化（9.x）、指针转换（11.x）、移位（12.x）、指针运算（18.x）、预处理（20.x）、库禁用（21.x 其余）六大类几乎空白** |
| SEI CERT C | 规则+建议百余条 | 5 | 整数溢出（INT30）、未初始化读（EXP33）、释放后使用（MEM30）、指针算术（ARR38）等安全主线缺失 |
| CWE（航天口径） | — | 4 | **文献结论：数组越界是航天嵌入式软件最高发缺陷**（陈睿 2021，§四.4.1），但我们只能判"常量下标"，变量下标未用上区间分析；NULL 解引用、算术溢出、栈大对象未覆盖 |
| GJB 8114（124 条强制） | 124 | 主题级映射，全部 verified=false | 授权文本未取得，合规结论暂不能输出 |
| 硬件语义 | §7 调研清单 8+ 项 | 4 | 保留位、位域越界、FromISR 细分、优先级约束、临界区成对性、ISR 非安全调用、volatile RMW 原子性、寄存器写序列——缺 8 条 |

**结论：30 条作为演示够用，但离"检测深度"的宣称和航天对接的规则对齐要求有明显缺口；缺口恰好集中在两类——通用高发缺陷（便宜可补）与硬件语义（差异化卖点）。**

## 三、补全清单

### 第一批 P0：硬件语义扩展（+8 条，差异化卖点，对接演示主力）

| 新规则 ID | 描述 | IR 检测思路（复用现有设施） | 依据 |
|-----------|------|---------------------------|------|
| `ECDET-HW-RESERVED` | 向 SVD 标注的保留位/保留寄存器写入非零值 | `svd.py` 扩展位域定义；写掩码常量与位域范围比对（常量传播已有） | CMSIS-SVD 规范；八项水土不服之② |
| `ECDET-HW-BITFIELD` | 位域赋值超出位宽（如 3 位域写入 0xF） | 写入常量 > 2^width-1 即报；变量值走区间 | SVD bitfield 定义 |
| `ECDET-HW-FROMISR` | ISR 内调用非 `FromISR` 后缀的 RTOS API | `isr.py`（已有 ISR 集）× `rtos_api.py`（加 FromISR 等价对） | FreeRTOS 官方规则；从 ISR-BLOCK 拆分 |
| `ECDET-HW-PRIORITY` | 中断优先级劣于 `configMAX_SYSCALL_INTERRUPT_PRIORITY` 却调用 RTOS API | 解析 `NVIC_SetPriority`/优先级常量，与配置宏比对 | FreeRTOS 官方规则 |
| `ECDET-HW-CRITICAL-PAIR` | 临界区原语不成对/嵌套不平衡（`__disable_irq`↔`__enable_irq`、`taskENTER↔EXIT_CRITICAL`） | `_critical_intervals` 已识别区间，补配对计数与跨函数不平衡 | CMSIS/FreeRTOS 语义 |
| `ECDET-HW-ISR-HEAP` | ISR 内调用 `malloc/free/printf` 等非 async-safe 函数 | ISR 集内禁用 API 黑名单（并入 `check_banned_apis` 思路） | CERT SIG29/POSIX async-safe |
| `ECDET-HW-VOLATILE-RMW` | 共享 volatile 变量的复合赋值（`\|=`/`&=`/`^=`/`++`）——读改写非原子，即使有保护读取也可能丢更新 | AST 模式匹配复合赋值目标 ∈ ISR 共享集（与 ISR-RACE 互补，不重复报警） | PASAN/CERT DCL? 系列；§7.2 |
| `ECDET-HW-REG-SEQ` | 固定写序列寄存器（解锁/密钥对，如 FLASH key、WDG feed）写序错乱或只写一半 | SVD 扩展 `<sequence>` 注记；同函数内序列模式匹配 | 各厂商参考手册通用模式 |

### 第二批 P0：通用高发缺陷（+6 条，便宜且命中航天文献痛点）

| 新规则 ID | 描述 | 检测思路 | 依据 |
|-----------|------|----------|------|
| `ECDET-CWE-457` | 自动变量未初始化即使用 | 文件内定值传播（`propagate_constants` 扩为"未定值集"），路径敏感可后置 LLM 分诊 | MISRA 9.1 / CERT EXP33-C；**航天文献第一类缺陷的伴生项** |
| `ECDET-CWE-787-VAR` | **变量**下标数组越界（现 ARR30-C 只判常量下标） | `proven_index_check` 反向利用：区间已证 > 上界即报；未知区间留给 LLM 分诊 | MISRA 18.1；航天文献最高发 |
| `ECDET-CWE-476` | 函数返回值未判空即解引用 | 已知返回可空 API 白名单（malloc/SDK 返回指针类）+ 局部传播 | CWE-476 / CERT EXP34-C |
| `ECDET-CWE-190` | 常量算术表达式溢出（乘加边界） | 常量传播的区间版：操作数区间外推 | CERT INT30-C / CWE-190 |
| `ECDET-CWE-785` | 栈上大对象（局部数组字面量尺寸超阈值，建议 1KB） | 声明处 sizeof 求值，阈值可配 | CWE-785；强实时栈深风险（呼应 17.2 禁递归） |
| `MISRA C:2012 17.7` | 非 void 函数返回值被丢弃（错误码被忽略） | 调用语句表达式丢弃判定 + 白名单（void 语义函数） | MISRA Required；航天代码错误处理基线 |

### 第三批 P1：标准覆盖面扩充（+14 条，规则量翻倍观感）

**MISRA（+8）**：
- **11.3/11.4** 指针类型转换——**寄存器映射强转 `(GPIO_TypeDef*)0x4002...` 的主场规则，与 MMIO 检测联动**（必做）
- **12.2** 移位操作数/计数越界；**14.4** 控制条件应为本质布尔；**15.6/15.7** 复合语句必须加花括号；**18.7** 禁用柔性数组成员；**20.10** 禁用 `#`/`##` 预处理操作符；**21.4** 禁用 `setjmp.h`（嵌入式异常语义不可控）

**CERT（+6）**：
- **INT30-C** 无符号溢出（区间检查复用）；**EXP33-C** 未初始化读（并入 457 引擎，双口径输出）；**MEM30-C** 释放后使用（释放点后引用传播）；**ARR38-C** 指针算术与非数组对象；**FIO34-C** 字符 I/O 函数返回值类型错误；**MSC33-C** 断言不得用于生产逻辑

### GJB 对齐路线（不新增实现，先打通合规口径）

1. `gjb_map.json` 已按主题建立映射、`verified=false` 不出合规结论的机制是对的；
2. 对接前动作：向对方/情报渠道申请 **GJB 8114-2013 授权文本**（124 条），回填 `gjb_id` 置 `verified=true`——即使只对齐 60%，"对 GJB 8114 有映射"本身是演示话术；
3. GJB 5369（航天 C 安全子集 138 条）同理，取得文本后按类别批量映射到 MISRA/CERT/自有规则。

## 四、排期建议（对接前 10 天）

| 时段 | 动作 | 产出 |
|------|------|------|
| 第 1-3 天 | 第一批硬件 8 条（`hw_model/` 扩展，全是已有设施的组合） | 硬件语义 4→12 条，PPT 页面从"4 条"升级为"12 条覆盖寄存器-中断-RTOS 全链" |

**演示口径建议**：PPT 上"30 条内置规则"可改为"58 条内置规则（MISRA/CERT/CWE/GJB 主题映射 + 12 条硬件语义）"，硬件语义从"4 条"单独强调为覆盖 **寄存器访问权限/保留位/位域/写序列（SVD 驱动）+ ISR 竞态/FromISR/优先级/临界区/非安全调用（中断语义）+ volatile 原子性** 三个层次——这正好逐条回应调研报告里通用工具的八项水土不服。

## 五、勘误备注

- `rules_meta.py` 模块 docstring 仍写"阶段一 MVP 规则集（24 条）"，与实际 30 条不符，实现时顺手更新；
- 新硬件规则沿用现有 `RuleMeta` 的 decidability 标注（`dataflow`/`syntactic`），保证 L4 分诊与人工评审路由不破坏。
