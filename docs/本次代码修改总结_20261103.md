### 2.1 硬件语义与代码上下文

SVD模型保存寄存器访问权限、字段位宽和写入语义。新增`ECDET-MMIO-W1C`规则检查明确标为写1清零寄存器的读改写操作，并保留地址、字段和源码证据。

Tree-sitter优先用于可信语法结构索引和LLM上下文切片，处理多行签名、UTF-8、CRLF、同行函数及静态函数作用域。宏、函数指针和条件编译中无法确定的调用保留未解析状态；缺少依赖或解析失败时记录原因并回退。现有静态规则仍保留原规则索引。

### 2.2 LLM、修复与证据约束

- 校验JSON结构、字段类型、有限置信度与正整数证据行。任一非法引用使整体证据校验失败。
- TP与FP共用证据门槛；缺失上下文、最终调用失败和低置信结果进入`NEEDS_REVIEW`。高危误报建议默认待复核。
- 修复前核对源码快照、函数身份、签名和修改范围，使用原规则、工程上下文及SVD重放检查；缺少必要验证时保留待验证状态。
- 检查harness的目标调用、激励和观测点，运行时核对目标进入标记；修正编译驱动时使用最新日志。
- 动态事件按文件、函数、缺陷类别和位置关联；无法精确关联时保留独立事件。
- 分诊、重判、补丁及harness调用共享任务预算，记录真实或Mock模式。预算限制调用次数，当前默认64次。

约束通过[项目开发要求](../AGENTS.md)和[LLM能力与验证约束](LLM能力与验证约束.md)固化，CLI、Web和编排入口复用相关校验。

### 2.3 三项新增分析后端

**libFuzzer**接收显式测试驱动和目标源码，启用覆盖率插桩、AddressSanitizer与UndefinedBehaviorSanitizer。字节接口可使用`generate_byte_harness`生成驱动模板。后端保存语料、覆盖记录、源码哈希、错误输入和重放日志；输入独立重放再次触发错误后才输出Detected事件。

**Z3**从实际源码提取受限C子集的整数类型、分支、赋值和局部数组访问，处理整数提升、无符号回绕及有符号运算定义条件。每项结果记录源码位置、输入位宽、SMT和候选输入，区分`SAT`、`UNSAT`、`UNKNOWN`、`UNSUPPORTED`和工具错误。

**Renode**接收ELF固件、REPL平台、UART接口与输出判据，完成加载、输入注入、有界执行和日志采集。结果检查读取独立UART文件，并通过脚本完成哨兵识别中途失败。固件、平台、源码哈希及重放脚本随结果保存。

### 2.4 网页“专项分析”

页面新增以下流程：

1. 选择已注册工程和分析类型。
2. 填写驱动、源码、固件、平台、输入及运行预算。
3. 保存Clang、Renode工具路径并查看可用性。
4. 提交后台任务，自动刷新状态或回看历史运行。
5. 查看告警与分项结果，下载HTML、SARIF、完整JSON和原始证据。

Z3候选显示“存在待验证候选”，libFuzzer重放成功显示“已复现错误”。工具缺失、超时、编译失败和部分检查未完成分别显示，保留已有日志与报告。

网页任务复用现有队列、运行记录、告警表和源码快照，没有修改数据库schema。工具设置与LLM配置分别保存。输入路径限定在注册工程内，下载同时核对运行目录和产物清单。

## 5. 安装与使用

Python最低版本为3.11，核心依赖仍为空。按需安装增强扩展：

```powershell
python -m pip install -e ".[hardware,syntax,constraints]"
```

| 扩展 | 固定依赖 |
| --- | --- |
| `hardware` | `cmsis-svd==0.6` |
| `syntax` | `tree-sitter==0.26.0`、`tree-sitter-c==0.24.2` |
| `constraints` | `z3-solver==5.3.3.0`，以及上述Tree-sitter依赖 |

libFuzzer需要支持相应插桩和运行库的Clang工具链；固件仿真需要Renode及匹配的平台描述。工具路径可在网页保存，也可通过`ECDET_CLANG`和`ECDET_RENODE`配置。

网页启动示例：

```powershell
python -m ecdet serve --port 8600 --data-dir webui_data
```

已有部署继续使用原数据目录，重启服务并刷新页面后进入“专项分析”。按表单填写工程内路径，首次使用先检查工具可用性。

命令行示例：

```powershell
python -m ecdet constraints examples/constraints_demo/bounds.c
python -m ecdet fuzz examples/libfuzzer_demo --harness harness.c --source packet_fixed.c --clang path/to/clang.exe --runs 5000 --timeout 20
python scripts/validate_renode.py --clang path/to/clang.exe --renode path/to/renode.exe --output-dir ecdet_reports/renode
```

## 6. 当前适用范围

- Tree-sitter提供结构索引和上下文，现有规则没有全部迁移到完整语义分析。
- Z3采用明确ABI下的局部C子集；SAT是待重放候选，UNSAT只对应记录的访问与模型。
- Renode本轮完成最小STM32F4模型的启动与UART交互验收，其他外设、中断和真实硬件需分别验证。
- 模型建议、引用有效、工具验证与人工确认分别记录；编译通过不代表业务行为等价。
- 原有源码动态扫描、覆盖率测试和固件仿真分别使用各自入口。Unicorn目前仍为可用性探测。
